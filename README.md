# سكني — Sakani App

منصة عربية تساعد الطلاب على البحث عن سكن ومقارنة الخيارات وطلب الحجز في دمياط ودمياط الجديدة ورأس البر. تجمع المنصة الطلاب ومُلّاك السكن وإدارة الموقع، وتعرض إشارات التوثيق بعد المراجعة الإدارية.

**الموقع:** [افتح سكني](https://sakani-student-housing-marketplace.replit.app)

## فكرة المشروع والعرض التقديمي

- [ملف فكرة المشروع وأهدافه](docs/PROJECT_IDEA.md).
- [ملفات العرض التقديمي القابلة للتعديل](artifacts/sakani-project-deck/).
- تم إعداد العرض في ملف **PDF** مستقل للعرض والمشاركة.

## التقنيات

- Next.js App Router وReact وTypeScript للواجهة والتطبيق.
- PostgreSQL وDrizzle ORM لإدارة البيانات.
- واجهة عربية باتجاه من اليمين إلى اليسار، متجاوبة مع الأجهزة المختلفة.

## التشغيل

```bash
npm install
npx drizzle-kit push           # إنشاء أو تحديث الجداول
npm run dev                    # أو npm run build && npm run start
```

استخدم قاعدة بيانات مخصصة للتطوير وراجع تغييرات المخطط قبل تنفيذ أمر Drizzle، لأنه قد يغيّر الجداول الموجودة. يوفّر Replit متغير `DATABASE_URL` عند استخدام قاعدة PostgreSQL المُدارة؛ لا حاجة لإنشاء ملف `.env` على Replit.

لا تُنشأ حسابات أو إعلانات أو حجوزات تجريبية. لإنشاء مدير المنصة الأول، اضبط `SAKANI_ADMIN_EMAIL` كمتغير بيئة، وأضف `SAKANI_ADMIN_PASSWORD` إلى Replit Secrets. ينشئ أول طلب لـ `/api/bootstrap` حساب المدير عند غياب الحساب.

## ما يعمل فعلًا

- بحث حقيقي من قاعدة البيانات: مدينة/جامعة/نوع/ميزانية/مرافق/مسافة/توثيق/تواريخ مع إتاحة محسوبة من الحجوزات النشطة، ترتيب، صفحات، ومقارنة حتى ٣ سكن.
- محرك تسعير خادم: إيجار نسبي للأيام، خصومات ورسوم قابلة للضبط، تنظيف وتأمين — تُحفظ التفاصيل مع طلب الحجز.
- محرك حجز يتحقق من الإتاحة والتداخل قبل إرسال الطلب، مع سجل لحالات الحجز. يظل الحجز بانتظار الدفع بعد موافقة المالك حتى ربط مزود دفع فعلي.
- الدفع الإلكتروني والاسترداد غير مفعّلين؛ لا يقبل الموقع بيانات بطاقات أو يدّعي تحصيل أموال.
- سياسة إلغاء قابلة للضبط من الإدارة، مع تسجيل طلبات الاسترداد دون تنفيذ مالي آلي حاليًا.
- توثيق بمراجعة بشرية: الشارة مرتبطة بسجل verification معتمد فقط؛ المالك لا يعتمد نفسه.
- لوحة مالك: إعلانات بحالات draft→pending_review→published…، وحدات وأسرّة وأسعار، طلبات حجز، تقييمات وردود، أرباح.
- مطابقة شركاء سكن بأوزان معلنة داخل نفس النوع فقط، مع أسباب التوافق، قبول/رفض/سحب، وإخفاء وسائل التواصل قبل القبول.
- رسائل داخلية، إشعارات، مفضلة، دعم، بلاغات، تقييمات مقصورة على إقامات مكتملة.
- إدارة شاملة: مستخدمون وأدوار وصلاحيات، مراجعة إعلانات وتوثيق، محتوى FAQ وإعلان، إعدادات عمولة/إلغاء/مدن/جامعات/مرافق، سجل تدقيق، تصدير CSV، وحالة التكاملات.

## حدود معروفة

- بوابة الدفع، SMS OTP، البريد الخارجي وتخزين المستندات: غير مفعّلة. لا تعرض الواجهة عمليات دفع أو بيانات سكن تجريبية.
- منع التداخل يتم بفحص داخل الخادم؛ للإنتاج الكبير يُنصح بقيد استبعاد PostgreSQL (btree_gist) أو قفل استشاري حول الوحدة.

راجع `docs/` للمعمارية والأمن والنشر والنسخ الاحتياطي وتقرير القبول.
